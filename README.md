# Master Group v417 — Local AI Router + exactly 10M external memory

## AI assistant

The service-name assistant now uses a **local multi-brain router**. The brains run first on the complete user phrase; the 10,000,000-entry dictionary is consulted only afterwards as supporting external memory. There is no server-side inference or paid API in this path.

### Whole-text behavior

The user input is treated as one semantic message, not as a sequence of words to correct. The local brains are instructed to infer the intent, actions, objects and relationships of the complete phrase and then generate one professional Russian service name.

Examples:

- `креплние мотра к рам` → `Крепление мотора к раме`
- `штробавко канала канализации` → `Штробление канала канализации`
- `разборко зборка квадрашкла` → `Разборка и сборка квадроцикла`
- `уклдк кафла ваной` → `Укладка плитки в ванной комнате`

### Local brains

The router knows three independent local ONNX brains:

1. **Qwen3.5-2B** — `onnx-community/Qwen3.5-2B-ONNX-OPT`
2. **Gemma 3 1B** — `onnx-community/gemma-3-1b-it-ONNX`
3. **DeepSeek-R1 Distill Qwen 1.5B** — `onnx-community/DeepSeek-R1-Distill-Qwen-1.5B-ONNX`

For noisy or multi-action phrases the router asks all three brains for whole-text candidates, then ranks them. The models are **loaded one at a time** and released after each response so the PWA does not keep all three models in memory simultaneously. For simple clean input the router starts with Qwen and avoids unnecessary model churn.

All three model families have browser/Transformers.js compatible ONNX distributions. Hugging Face documents direct WebGPU execution in the browser; Safari/iOS support remains device/browser dependent.

### 10M memory

The 10,000,000 records remain an external reference layer. They are not the primary correction engine and they do not perform visible sequential word replacement. Memory is used after the brains have proposed whole phrases, to validate terminology, support ranking and ground candidates in Master Group catalog knowledge. A phrase may be absent from memory and can still be generated by the brains.

### First-run behavior

The ONNX weights are fetched on first use and cached in the browser. Inference is local after the model is available on the device. WebGPU is preferred; WASM is the fallback where supported. Because the app is hosted on GitHub Pages, the first model download needs internet access.

The original service text is never replaced automatically. The user must explicitly select the AI suggestion.

### Tests

The project contains smoke tests for the three-brain router, whole-text behavior, 10M integrity, PWA updates and the existing application subsystems.

## UI change in v383
The AI suggestion is now positioned as a compact floating layer above the service input. It is removed from normal document flow, so the input, Add button, service list, and modal height do not move when the suggestion appears.



## AI v408 semantic brain
The service-name assistant treats the 10,000,000-entry index as external memory, not as a phrase database. It repairs candidate word forms, resolves morphology/context, constructs unseen phrases, and uses a local language model only for hard cases. The user's original text is never replaced without an explicit tap on the suggestion.

## v410 whole-text semantic memory
The service-name assistant treats the entire user string as a semantic request first. The 10M dictionary is supporting external memory; visible suggestions are taken from phrase/catalog memory and action+object concept retrieval, not from per-token replacement. A relevance gate rejects candidates that lose the main object of the request. Single nouns open a phrase neighborhood (e.g. “багажник” → “Установка багажника”, “Монтаж багажника”, …).


## v416 — Whole-text AI brain
- Qwen3.5-2B is the primary local AI stage for multi-word service phrases.
- The 10M dictionary is external retrieval memory only; it cannot produce visible multi-word answers through token-by-token substitution.
- Model loading is lazy: the model is not warmed at page start, reducing unnecessary memory pressure on iPhone/PWA.
- AI analysis is debounced to 650 ms after typing stops.
- A final relevance/quality guard rejects malformed, duplicated, irrelevant, or grammatically broken candidates.


## v417 — Local multi-brain router
- Three local whole-text brains: Qwen3.5-2B, Gemma 3 1B and DeepSeek-R1 Distill Qwen 1.5B.
- Brain-first ordering: `whole input -> AI brains -> choose best candidate -> 10M memory validation`.
- No token-by-token visible correction path for multi-word input.
- Only one model is kept loaded at a time to reduce peak device memory.
- Model status and run counts are exposed through `MG_AI_SERVICE.getStatus()`.
